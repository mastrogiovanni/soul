03 / MADE FOR WORK THAT CAN WAIT

Less busywork.
More time for your mission.

Some answers are useful even when they arrive later. Soul is intended for batch systems and background processes whose value does not depend on a real-time response.

01 / INBOX

Email processing

Sort incoming messages by topic, summarize long threads, and prepare reply drafts for volunteers to review when they next check the shared inbox.

02 / ADMINISTRATION

Invoice analysis

Turn extracted invoice text into draft records of suppliers, amounts, dates, and expense categories for a treasurer to check before entering them in the accounts.

03 / OPERATIONS

Process improvement

Review activity notes and recurring support requests to spot repeated steps, slow handoffs, and opportunities to simplify everyday work for the team.

04 / FUNDING

Grant opportunity summaries

Summarize public funding calls, pull out deadlines and application requirements, and prepare a reading list for the next fundraising meeting.

05 / COLLABORATION

Meeting follow-ups

Turn existing meeting notes or transcripts into draft minutes, decisions, and action lists, ready for the coordinator to review and share later.

06 / OUTREACH

Multilingual communication

Prepare translation drafts and plain-language versions of event announcements, newsletters, and volunteer guides for people to review before publication.

07 / SHARED KNOWLEDGE

A more useful document archive

Summarize and suggest topic tags for extracted text from older reports, guides, and project notes, helping volunteers find useful information in the organization’s existing archive.

08 / LISTENING

Community feedback digests

Group anonymized survey comments and event feedback into themes, recurring questions, and suggestions for the team’s next planning session.

09 / REPORTING

Impact report drafts

Bring together program updates and volunteer activity notes into a draft monthly narrative, with the team checking the facts and figures before it goes to supporters.

Collect the work. Process it in the background. Review it later.

These are workflow ideas you can build with Soul. Your application or automation tool handles scheduling, text extraction, retries, and saving results; Soul provides the language-model inference. Completion time depends on the model and available network capacity.

BEFORE YOU CONNECT

A good fit for your machine.

  • Apple Silicon macOSRun natively, with Metal or CPU.
  • Linux x86_64 or ARM64glibc 2.28+. CPU or supported NVIDIA GPU.
  • Memory, disk & connectionThe agent uses your resources and downloads assigned weights. Initial setup can take several minutes.
Installation options, resource limits & troubleshooting +

Choose your contribution

Set a node name and an 8 GiB memory budget. This is a planning budget, not hard resource isolation. 

curl -fsSL https://mastrogiovanni.ddns.net/soul/install.sh | bash -s -- -- --name my-soul-node --memory-gb 8

Restart when you’re ready

~/.local/share/soul/bin/soul-node

The default budget is 75% of available device memory. Model tensors stay on disk for reuse; there is no automatic disk quota. Electricity, bandwidth, and hardware are your contribution. The agent does not install a boot service.

Check the fit

NVIDIA requires a working driver and compatible CUDA profile. Native Windows, Intel Macs, and Alpine/musl are not supported by this installer. Windows users can use a supported WSL2 Linux environment.

If you can’t connect

Check your internet connection and ~/.cache/soul/node.log. If the installer is unavailable or enrollment is rejected, contact the operator. If the controller requires an additional sign-in, the operator must provide those credentials.

A FEW THINGS TO KNOW

Good questions.
Clear answers.

Why accept higher latency?+

Soul prioritizes helping communities and nonprofits access large language models with less setup effort by sharing available machines. This can mean longer, variable waits. Email digests, document processing, and periodic reports can still be useful when completed later. Applications that need immediate, predictable responses are a less suitable fit.

Does Soul include a batch job platform?+

Soul currently provides inference APIs with a bounded request queue and one active generation at a time. It does not include a durable background job service or a dedicated Batch API. Your application schedules individual inference calls, saves progress, and retries failed work. The use cases above are ideas for integrations, not preinstalled applications.

Does more compute mean more speed and redundancy?+

More suitable nodes add memory capacity and placement choices. The controller can repair missing model stages when enough capacity remains, and reusable cached tensors can reduce preparation time. Today Soul runs one active generation at a time. A disconnected node can interrupt a request, and adding stages can add network latency. There is one controller; automatic controller failover, replicas, and concurrent pipelines are future work.

Can I use the system after I join?+

Members can use prepared models with an inference API key supplied by the operator. Node enrollment and inference access use different credentials. Model availability depends on connected capacity, and the operator manages the catalog. This site does not create an account or issue a key.

What am I sharing, and can I stop?+

Your node contributes memory, processing, disk space, electricity, and network bandwidth. You can set a memory budget and stop the foreground agent with Ctrl+C. Downloaded model files remain cached for reuse. Stopping a node that is serving a model can interrupt an active request.

Which models can the community run?+

Soul currently supports standard, unquantized safetensors models with llama, mistral, qwen2, or qwen3 architectures. Availability depends on administrator preparation, model permissions, and network capacity. It does not provide proprietary OpenAI or Anthropic models; its APIs use compatible request formats.

Is this a private place for sensitive prompts?+

Participating nodes process prompts, intermediate activations, and parts of the model. Only use a network whose operators and contributors you trust, and avoid sending confidential information to an untrusted community. HTTPS protects connections; it does not hide computation from the machines doing the work.

Where do I get help?+

Start with the installation options above or the controller’s API reference. For enrollment, an inference key, or an additional controller sign-in, find the operator on GitHub.
