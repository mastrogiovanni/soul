You must create a project for distributed training. The project will consist in a distributed network of agents that are able to perform serving of a model as a single soul. No need to have a peer to peer network: we can use a star topology: a central backend that we will call "controller" that will receive the API requests and a set of clients or "nodes" that will connect to it to exchange information about host capability, to receive data to process and that returns data processed.
The mental model used here is the following: an LLM has a series of layers, each one take an input and return an output. We want to distribute the load on different computer in an orschestrated way so that for example, if we are running inference for a model that has layer 1 to 10 an host can have layers from 1 to 4, anoter node will have from 5 to 7 and another from 8 to 10. Then the computation is passed to the first node and then results are returned, the results are passed to the second node, the results are passed to third node and results are returned back to the user.
The API we want to support are the standard one from OpenAI or antropic, streaming and text. The system should be able to work on any model downloadable from hugging face and that correspond the the LLM architecture.
There could be other aspects of serving that worth to consider: rotation, kv cache, SSD streaming and many more. If they can be distributed then the business logic must be on the clients, if not it must lie on the server and a furher data passing or method calling must be performed between node and controller.
For example a node that hosts the initial layer could ask embeddings for the KV Cache to the controller or simply the controller can send them with the data. Is up to you to decide the best strategy.
We want to be able to run nodes on both Mac and NVIDIA GPUs.
The controller must be pure orchestrator, can have CPU bound and memory (RAM) processes but in theory it could be as simple as a Raspberry PI. If this is not possible (for example because you need several Gigabytes of RAM to host the KVCache) dont' worry and assume that the device is not constrained.
The nodes should be able to select the best size that they can host for each model with some raw estimation, they must be able to keep weight (only for the layers assigned to them) locally in a disk storage to load them in the GPU.
You can choose the language you want for controller and nodes but keep as simple as possible the installation of the nodes so that people can join without problems.
When a controller is asked for an inference on a given model he first try to establish the size of the model and try to split the layers among the nodes he has.
You can assume the network is stable so that each node has its own identity and they will be restarted after a fail.
The controller can keep track of what layers are on which nodes and force them to restart computation when they reconnect (he can keep a queue and can return a 5xx error if is not possible to make the inference).
I want also an UI to connect to the controller (or that is exposed by it) so that I can see the models loaded, where they are distributed, how many inference were executed, status of each client (layer downloaded or in downloading). From the admin UI must be also possible to see logs in each client and see the status they are.
When everything is finished we will proceed with phase 2. In order to let you decide at the best architecture and technologies I want to let you know that we planned to create clients that will run also on cellphone and that will leverage on the cellphone GPU to perform as nodes. In that case you will be free to choose the use WebGPU (from an open web page) or a custom binary to install on the device like an app.
